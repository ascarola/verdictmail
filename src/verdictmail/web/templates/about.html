VerdictMail

AI-Powered Email Threat Analysis

v0.3.9
What It Does

VerdictMail is an autonomous email security daemon that monitors an IMAP inbox via IMAP IDLE and runs every incoming message through a multi-stage analysis pipeline in real time — without any user intervention.

Parse Extracts headers, sender identity, originating IP, and all URLs from RFC 822 message bytes.
Enrich Checks SPF, DKIM, DMARC, domain age (WHOIS), DNSBL reputation, display-name spoofing, and expands shortened URLs.
AI Analysis Sends a structured prompt containing all enrichment signals to an LLM (OpenAI, Anthropic, or a local Ollama model) and receives a JSON threat assessment with confidence score and reasoning.
Decide & Act Applies configurable confidence thresholds to produce a final action — pass, flag (IMAP keyword), or move to junk — then logs the full result to a SQLite audit database.

Analysis Pipeline
IMAP IDLE Parse RFC 822 Enrich AI Analyze Decide Audit Log

Each message is processed concurrently in a dedicated thread with its own IMAP connection. The full pipeline typically completes in under 15 seconds with a cloud AI provider.

Deployment

VerdictMail runs as two systemd services on a dedicated Ubuntu 24.04 LXC container hosted in a Proxmox homelab environment:

  • verdictmail.service — the analysis daemon (IMAP IDLE loop + worker threads)
  • verdictmail-web.service — this Flask admin interface (port 80)
Release Notes
v0.3.9 Security: hardened redirect validation
  • Closed two open-redirect gaps in the post-action redirect helper: backslash payloads (/\\evil.com) that browsers normalize into an external host, and CR/LF/control characters used for header injection. Only single-slash-rooted local paths are now accepted.
  • Resolves CodeQL py/url-redirection alerts.
v0.3.8 Blacklist (always junk) & recalibrated thresholds
  • New Blacklist: senders matched against user rules skip analysis and move straight to junk — an override for senders that ignore unsubscribe requests. Managed on a new Blacklist page or via the Junk Sender button in the Audit Log detail view. Takes precedence over the whitelist.
  • Aggressiveness presets recalibrated to the confidence range LLMs actually emit (previously three of the four presets behaved identically).
  • New custom flag/junk threshold inputs on the Configuration page for models whose confidence range doesn't match the presets.
  • Decision rule tweak: a high-threat verdict with an aggressive AI recommendation now requires confidence at the midpoint of the flag/junk thresholds (previously only the flag threshold, which could bypass the junk threshold entirely).
  • Audit detail view no longer shows "recorded before v0.3.3" for whitelisted/blacklisted messages — it now explains that enrichment was skipped by rule.
v0.3.7 Suspect folder & visible flag action
  • New imap.suspect_folder config key: medium-threat (flagged) messages can be moved to a dedicated IMAP folder instead of remaining in the inbox.
  • When no suspect folder is configured, flagged messages are now starred (\Flagged — the Gmail yellow star) rather than the previously invisible $VerdictMail-Suspect keyword.
  • New IMAP Folders card on the Configuration page for UI-based folder management.
  • Install script now prompts for a suspect folder and validates it against the IMAP server.
  • Switched default model recommendation to gemma4:e4b for faster processing (~14s vs ~50s).
v0.3.6 JSON robustness & Ollama multi-model safety
  • Added json-repair fallback parser; removed assistant prefill that caused truncated JSON.
  • Removed num_ctx override from Ollama requests to prevent model reloads that disrupted other users.
  • Updated default Ollama model recommendation to gemma4:26b.
v0.3.5 AI response resilience
  • JSON nesting unwrap: handles models that wrap responses in {"analysis": {...}}.
  • Fixed WHOIS log suppression (corrected from WARNING to CRITICAL level).
v0.3.4 Ollama reliability
  • Added "format": "json" to Ollama requests for grammar-constrained JSON output.
  • Added "think": false to suppress reasoning tokens on thinking-capable models.
